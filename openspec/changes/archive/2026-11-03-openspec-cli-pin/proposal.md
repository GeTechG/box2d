## Why
Nothing pins or checks OpenSpec here: agents used whatever global `openspec` they found (now gone), the skills were generated by 1.13.2, one archived change was written by hand without `.openspec.yaml`, and two main specs fail `openspec validate --all --strict` of 1.16.0 without anyone noticing.

## What Changes
- `openspec/cli.pin` — one line, the OpenSpec CLI version (`1.16.0`) this repository is worked with.
- The OpenSpec skills in `.claude/skills/` and `.agents/skills/` regenerated by that version.
- A CI job `openspec` (script `openspec/check.sh`, runnable locally) that runs the pinned CLI and fails on: a strict validation error or warning, a main spec whose Purpose is the archive placeholder, an active change without `.openspec.yaml`, a skill whose `generatedBy` is not the pin, an archived change with an open task that is not `[human]`.
- `openspec/config.yaml` gains `rules.specs`, `rules.tasks` and `operations.apply`/`operations.archive` guidance that points at `AGENTS.md`.
- The two specs that fail strict validation are fixed: `commit-kinds` gets a scenario for its second requirement; the long requirement of `contact-inv-mass-scales` is split without losing anything.
- `AGENTS.md` records the pin, how to bump it, and the new check.

## Capabilities

### New Capabilities
- `openspec-workflow`: which OpenSpec CLI version the repository uses, the skills it generates, and the CI check that keeps specs, changes and skills valid.

### Modified Capabilities
- `commit-kinds`: the self-test requirement gains a scenario (no behaviour change).
- `contact-inv-mass-scales`: the first requirement is split into shorter requirements with the same meaning (no behaviour change).

## Impact
Infrastructure only: `openspec/`, `.claude/skills/`, `.agents/skills/`, `.github/workflows/ci.yml`, `AGENTS.md`. No library code changes.
