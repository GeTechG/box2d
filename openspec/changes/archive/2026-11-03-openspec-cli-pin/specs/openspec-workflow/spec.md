## ADDED Requirements

### Requirement: The OpenSpec CLI version is pinned
`openspec/cli.pin` SHALL hold one line, the version of `@fission-ai/openspec` that every OpenSpec command of this repository (by agents and by CI) runs with.

#### Scenario: CI runs the pinned version
- **WHEN** the `openspec` CI job runs and no global `openspec` of the pinned version is installed
- **THEN** it runs `npm exec --yes --package=@fission-ai/openspec@<pin> -- openspec`

#### Scenario: Version bump
- **WHEN** the pin is changed to another version and the OpenSpec skills are not regenerated with it
- **THEN** the check fails and names every skill whose `generatedBy` is not the new pin

### Requirement: The OpenSpec skills are generated by the pinned version
The OpenSpec skills (propose, explore, continue, apply, update, ff, sync, archive, bulk-archive, verify) SHALL be committed in `.claude/skills/openspec-*` and `.agents/skills/openspec-*`, generated by the pinned CLI, and their `generatedBy` SHALL equal the pin.

#### Scenario: Stale skill
- **WHEN** a committed skill has `generatedBy: "1.13.2"` and the pin is `1.16.0`
- **THEN** the check fails and names the skill file

### Requirement: CI validates the OpenSpec tree
The `openspec` CI job SHALL run `openspec/check.sh`, which SHALL fail when `openspec validate --all --strict` reports any error or warning, or when any rule of this capability's other scenarios is broken.

#### Scenario: Strict validation warning
- **WHEN** a main spec has a requirement longer than 500 characters
- **THEN** the check fails with the validator's message

#### Scenario: Placeholder Purpose
- **WHEN** a main spec's Purpose starts with `TBD - created by archiving change`
- **THEN** the check fails and names the spec

#### Scenario: Change written by hand
- **WHEN** an active change directory under `openspec/changes/` has no `.openspec.yaml`
- **THEN** the check fails and names the change

#### Scenario: Open task in the archive
- **WHEN** an archived change's `tasks.md` has a `- [ ]` line without `[human]`
- **THEN** the check fails and names the line

#### Scenario: Open human task in the archive
- **WHEN** the only open tasks of an archived change are marked `[human]`
- **THEN** the check passes
